Skip semantics (verified against plan text line 197, NOT assumed):
  - lookup = NEWEST record with matching key must be PASS ∧ ¬degraded ∧ llm===mode
    ⇒ a FAIL recorded AFTER a PASS invalidates the skip (fail-closed newest-verdict reading;
    lock-step implemented in lookupSkipRecord/latestPassCoveringTargets, unit test asserts it).
  - cached FAIL is therefore never replayed: each blocked re-run re-derives exit 1 + appends audit record.
  - SKIP prints exactly `SKIP <key8> — PASS <ISO ts> report <path>` (D6) and exits with the
    CERTIFIED run's verdict (PASS ⇒ 0).
  - degraded ⇒ exit 2 regardless: runCheck returns before recordCheckRun; degraded consult never
    skips (probeDegraded ⇒ no record, no skip — ledger line count unchanged, asserted).
  - NO-OP ⇒ recordCheckRun throws /NO-OP/; refusal leaves no ledger file behind (unit test).

Retention AC: 25 seeded run dirs ⇒ exactly 20 newest survive, oldest collected, other key8 untouched,
no-runs-dir ⇒ no-op. Ledger lines are NEVER pruned (append-only). test/ledger.test.ts.

Failure AC — corruption tolerance (hand-corrupted lines must not brick):
  - unit: invalid JSON + unknown t + SIGKILL-torn tail (no trailing \n) + blank lines ⇒ every bad line
    becomes `ledger line N unreadable (reason) — line skipped`, valid records intact, lookups work.
  - CLI: two corrupt lines appended ⇒ stderr WARNINGs + SKIP still honored, exit 0 (manual QA below).
  - hand-forced degraded:true ⇒ rejected at PARSE (never becomes a record).

Atomicity/concurrency: appendRecord writes ONE serialized line via appendFileSync(…, flag a) ⇒
single write syscall of one buffer under O_APPEND (plan: "single writeFileSync append of one-line JSON,
atomic enough for append; concurrency blocked by lock anyway"). Torn writes read back as corrupt lines.
