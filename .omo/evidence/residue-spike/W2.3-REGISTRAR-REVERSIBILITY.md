## 2. Real persistence mechanism (verified from published bytes, not the reference narrative)

### 2.1 The registrar owns config-JSON persistence; npm lifecycle owns NOTHING
Published `opencode-hr-agent@0.2.2` `package.json` has **no install/postinstall hooks** (header comment at
`install-cli.js:1-6` states this as design: "no lifecycle scripts"). Empirical: trace A PHASE 1 — full
`npm install -g` of the chain changed **zero** files outside npm's own tree/cache. Persistence happens only when
something *invokes the bin*: `opencode-hr install` writes `plugin` arrays into `$OPENCODE_CONFIG_DIR` (default
`~/.config/opencode`) via `readConfig → mergePlugins → writeAtomic` (`install-cli.js:40/56/81`;
`writeFileSync(tmp, JSON.stringify(data, null, 2)+"\n")` at `:93` is the re-format lesion). JSONC files are
refused untouched (`:30-36`). The wheel's `run_setup` (published `cli_setup.py:94-135`) chains exactly:
`npm install -g <pins>` (`:103`) → `_find_registrar` (`:79`) → `[registrar, "install"]` (`:120`) → `status` (`:127`).

## 5. CLI gaps found (roadmap candidates)

1. **G-LOCAL — roundtrip cannot target local artifacts.** spec grammar is `[ecosystem:]name@version` only. Probes
   (`traceE-cli-gap-probes.txt`): `/tmp/…/opencode-hr-agent-0.2.2.tgz`, bare `opencode-hr-agent`,
   `npm:file:/…tgz` → all exit 2 `spec … missing '@version'`. Workaround used here = manual containers with the
   tarball bind-mounted (`:ro`). Candidate: accept a path/`file:` spec, or `--artifact <tgz> --eco npm`.
2. **G-RUN — roundtrip cannot drive declared verbs beyond lifecycle.** Need a per-spec invocation profile
   (e.g. `--install-cmd "opencode-hr install" --uninstall-cmd "opencode-hr uninstall"`, or auto-derive from
   `package.json` `bin` + README). Without it, npm-registered persistence (this whole family) measures as clean.
3. **G-RELEASE — the paired PATH writer is unreleased (as of this spike).** `v0.3.0` is tagged but not on PyPI
   (§2.2 temporal note). When its wheel ships, the roundtrip pypi profile still won't execute `hr setup` (same
   G-RUN class) — the marker-block reversibility must then be proven by an invocation profile or the pairing
   stays static-only.
4. **G-WRITER (hr-side, exact lines):** to make surface 4 byte-reversible, `install-cli.js` needs the
   `setup_env.py` pattern ported from reference (MARK_BEGIN/MARK_END :34-35, `remove_posix` :156 "delete only what
   you created"): i.e. pre-image capture in `install()` (`:106-131`) and restore-not-refilter in `uninstall()`
   (`:148-169`), replacing blind `JSON.stringify(_,null,2)` (`:93`); delete a file it created, never inject a
    `"plugin": []` key it didn't own. JSON can't hold line markers — pre-image snapshot (`.bak` under
    `~/.local/state/opencode-hr/`) is the honest analogue.
5. **G-CALIB — the pypi roundtrip profile emits a dependency-closure storm.** `pip uninstall -y <name>` removes
   only the target by design, so whole-FS diffing flags the *entire* closure as residue: trace F = 2210 of 2211
   rows are deps (numpy alone 990; +8 dep console-scripts in `/usr/local/bin`), burying the one artifact-owned row
   (orphan dir `/usr/local/share/aihr`). The npm leg has no such issue (trace D: `npm uninstall -g` is
   closure-symmetric → 0 rows). Honest-but-unusable as a per-artifact gate. Candidates: (a) closure teardown before
   the post-uninstall hash (freeze-diff loop); (b) attribute rows via the target's RECORD + created-parent dirs and
   severity-downgrade non-target closure; (c) per-ecosystem expected-residue allowlist. Without one, `roundtrip`
   pypi verdicts FAIL for *every* package with deps.

## 6. Honest conclusion vs the constitution (paired reversibility)

| Family surface | Paired-reversible TODAY? | Basis |
|---|---|---|
| npm-managed tree (install/uninstall -g) | **YES** | manager-enforced; trace A P1/P4 byte-delta zero |
| PyPI wheel RECORD files (site-packages + `data_files` contents) | **YES** | manager-enforced; `hr/` module + 7 configs removed (trace F, trace G) |
| PyPI wheel `data_files` parent dir (`/usr/local/share/aihr`) | **NO — directory-level residue** | trace G: `pip uninstall` deletes the 7 files but reclaims neither the empty dir nor its parent |
| shell rc / PATH | **VACUOUSLY** (published chain writes no rc at any level — K5 confirmed empirically) | traces A/B `sha256sum -c` invariant; wheel grep = 0 persist/uninstall |
| opencode config JSON (registrar) | **NO — LEFTOVER-MODIFIED** | §3.1/§3.3: `{"plugin": []}` file pair + added key + re-format; no pre-image, no markers |
| published wheel removal | **NO-REMOVAL-PATH-EXISTS** (wheel ships zero inverse; `--uninstall` is `No such option`) | trace B P5; §2.2 (fix is committed at HEAD, unreleased) |

The chain today satisfies the constitution only where the *package managers* do the work — and even that is
incomplete: `pip` reclaims RECORD file bytes but not the directories it created. Its own persistence (config JSON)
has a semantic inverse but not a byte one; its PATH layer ships nothing and the real writer waits in unreleased
HEAD. Border's 0.4.0 roundtrip valve validated the npm surface correctly (trace D: 0 rows, PASS), caught a real
pip directory-residue row the manual `/root`-scoped instrument missed (trace F/G), yet remains structurally blind
to the registrar's bin-invoked config residue. G-RUN + G-CALIB are the concrete next wedges for W2.4/W3, and
W2.3's verdict table is their fixture.
