BLOCKED` lines), recordPushSuccess (t:"push" via buildPushRecord+appendRecord).

Contract coverage:
* PUSHED computed LIVE, never from ledger alone:
  - git legs: `git ls-remote <url>` FULL-REF comparison vs ctx.refSet
    (gatherContext); tags compared as PEELED commits — remote `refs/tags/X^{}`
    line wins, local side resolves annotated tags via for-each-ref
    %(*objectname); remote ref absent => "absent" (first push, never "equal").
  - npm/pypi legs reuse todo-13 runRegistryProbes version-exists polarity:
    present + our t:"push" record for exact `name@version` => PUSHED;
    present + owner==self (no name-foreign-owner finding) => PUSHED
    (lost-ledger recovery); present + foreign/ambiguous owner + no record =>
    BLOCKED delegating VERSION_EXISTS_RULE/BUMP_VERSION_MESSAGE ('bump version
    required') — squatter NEVER silently PUSHED (round-1 M4); absent => PENDING;
    unreachable => EngineRunError propagates (exit 2, fail-closed pinned in 13).
* PASSED gate: latestPassCoveringTargets(records, CURRENT fp.key, [kind]) —
  re-keyed via computeFingerprint (key binds refSet+exposure => stale PASS
  impossible). Neither PASSED nor live-PUSHED => BLOCKED reason
  "unchecked: no PASS record ... run 'border check' first". pushstate NEVER
  runs checks itself.
* No force-push anywhere, no tag cherry-picking, no state beyond ledger+probes
  (grep "force" src/pushstate.ts: only the header's negation prose).

== DESIGN DECISIONS (deviations/seams, documented per briefing) ==
1. API shape: derivePushState takes {cfg, configDigest} (not the LoadResult) —
   configDigest is exactly what the check flow (commands/check.ts) computes via
   computeConfigDigest(load); todo 17 has both at hand. No sibling file touched.
2. pushableTargets returns PENDING only. Plan says "attempt ONLY non-PUSHED
   targets"; BLOCKED targets are also non-PUSHED but pushing them is precisely
   what the gate exists to prevent (unchecked content / squatted version), so
   the resume set = PENDING. The tri-state line preserves the distinction.
3. Unreachable-remote error text deliberately DROPS the runGitChecked cause
   string (it echoes the raw credential-bearing url); message carries the
   sanitized url + target id instead (G20/G23 hygiene).
4. fetcher? passthrough to RegistryProbeOptions (todo-13's existing test seam)
   exposed on PushStateOptions — optional param, zero prod impact, pypi-leg
   testability for todo 17.
5. runGitChecked timeout is 60s (spawnSync, context.ts) — a hung ls-remote
   surfaces as the same PushStateError exit-2 path (kind: "could not spawn").

== ULTRAQA TRIGGER MAP ==
* malformed_input: parseLsRemote fail-closed on garbage/no-tab/bad-hex lines
  (PushStateError, names target); HEAD line whitelisted-but-skipped; ledger
  garbage handled upstream by readLedger warnings (surfaced in PushStateResult).
* stale_state: G43 IS the AC — tag deleted on B => B PENDING despite equal
  branch tip; PASSED gate keyed to the CURRENT fingerprint (refSet+exposure in
  the key) so a stale PASS cannot certify.
* hung_commands: ls-remote bounded by runGitChecked 60s spawnSync timeout;
  both the dead-dir and the timeout path raise exit-2 errors naming the target;
  registry timeout (15s, todo 13) rejects EngineRunError (covered: closed-port
  test; hanging-registry polarity already pinned in test/registry.test.ts).
* misleading_success_output: squatter can never read as PUSHED — record or
  owner==self proof required (AC test); "PUSHED(no-op)" only from live equality.
* cancel_resume: matrix above; pushableTargets drives `push --yes`.
* dirty_worktree: PUSHED claims derive from refSet+probes only — test drives a
  dirty untracked file + detached HEAD with an empty ledger and still gets
  PUSHED(no-op) for the synced remote.
