ITEM 1 — fix(push): bounded timeout on real git push
(src/push/git.ts executePush; test/push.git.timeout.test.ts)
---------------------------------------------------------------------

MECHANISM
- spawnSync `timeout:` option (precedent: src/check/context.ts 60s,
  src/check/tagScan.ts 300s — no SIGTERM->SIGKILL escalation exists
  anywhere on the spawnSync path, so none was introduced).
- Default PUSH_TIMEOUT_MS = 120_000 (documented: slow-link push + one
  credential round-trip). Override: BORDER_PUSH_TIMEOUT_MS
  (positive-integer ms; same test/ops-seam spirit as
  BORDER_PROMPT_TEMPLATE_PATH). Malformed value throws PushStateError
  BEFORE spawning — fail closed, never silently defaults.
- Discriminator: Node 22 spawnSync answers a budget kill with
  {status:null, signal:"SIGTERM", error:ETIMEDOUT}; a genuine spawn
  failure keeps signal:null. Branch order: signal-first, THEN r.error.
  (First fix iteration checked r.error first and mislabeled the
  timeout as "git could not start (spawnSync git ETIMEDOUT)" — the
  new tests caught it, see interim RED below.)
- Fail-closed contract: timeout => {ok:false, failure:"...timed out
  after Nms (BORDER_PUSH_TIMEOUT_MS) and was killed by signal SIGTERM
  -- the remote state is INDETERMINATE: verify with 'git ls-remote
  <sanitized url>' and rerun 'border push --yes' (safe: landed remotes
  come back no-op)"}. Caller (src/commands/push.ts, sibling-owned,
  untouched) interpolates it into "border: PARTIAL push ..." and
  returns EXIT_BLOCKED with ZERO recordPushSuccess calls — no ledger
  entry is possible on ok:false.

TEST FIXTURE
- PATH-stub git: passthrough for everything except `push`, which does
  `echo $$ > $BORDER_TEST_STUB_PID; exec sleep 10`. exec keeps the PID,
  so the pidfile IS the sleeper -> lingering-process check is a
  kill(pid,0) liveness probe. (GNU sleep would reject a marker argv, so
  the pidfile technique replaced the pgrep -f marker plan.)
- 3 tests: unit kill+bound+message+no-linger; malformed-env table
  (0, -5, abc, 12.5) must throw PushStateError pre-spawn; e2e
  `border push --yes` exit==EXIT_BLOCKED, stderr names
  /timed out/i /indeterminate/i /ls-remote/i, 0 push records, bare
  untouched, stub dead.

INCIDENT (honesty note)
---------------------------------------------------------------------
While aborting the `npm test` lifecycle-proof run (only the banner was
needed), `pkill -f "register-ts..."` matched the CONCURRENT SIBLING
worker's in-flight `node --test test/llm.test.ts` (pid 2677141) and
killed it. Their targeted run must be re-executed; no files were
touched by the kill (the test runner only reads its sources). The
authoritative signal stands: the full `npm test` immediately BEFORE
this incident passed 334/334, llm.test.ts included.
Lesson recorded in notepad: never pkill -f a substring that appears in
other workers' legitimate processes; kill recorded PIDs of known-own
orphans only.
