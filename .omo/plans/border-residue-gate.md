# border-residue-gate (0.3.0, roadmap to 0.4.0) - Work Plan

## TL;DR (For humans)

**What you'll get:** border learns to answer "does this package leave garbage behind when uninstalled?" — and gates the answer. The design copies the pattern we dissected live from opencode's npm install: PATH entries are machine infrastructure set up ONCE; a package only declares its `bin`, and the package manager's own ledger (symlink in the global bin dir, files under the install root) records every byte the install touches, so uninstall reclaims everything by construction. Border enforces that discipline as a rule family: anything an install-time script writes must stay inside the install tree or be manager-recorded; touching the user's shell config, downloading unaudited bytes, or registering persistence (cron/systemd/autostart) is blocked — regardless of npm/PyPI/crates/RubyGems.

**Why this approach:** "uninstall runs a cleanup script" (the first instinct) reopens the exact hole border exists to close — an uninstall hook is arbitrary code at the most unmonitored moment, and npm/pip/cargo make such scripts unreliable or impossible. The opencode anatomy proved the better contract: **don't create residue you'd need to clean**. So the gate classifies install-time *capability* into five tiers (T0 recorded / T1 in-tree / T2 network / T3 out-of-tree / T4 persistence) instead of banning all lifecycle scripts wholesale — opencode-style tree-local postinstall passes with a warning; rc-editing and downloaders block.

**What it will NOT do:** no uninstall-cleanup-script enforcement yet (sandbox round-trip is 0.4.0's exception valve; 0.3.0 has no pairing downgrade path at all); no runtime/first-run write gating (config dirs created on first launch are user state, honest docs only); no generic taint analysis of JS/Python/Ruby/Rust (a CLOSED signature table matches scripts, anything unmatchable keeps today's blocking default); border never modifies, removes, or "cleans" anything on the user's system — it reports and blocks.

**Effort:** Medium (5 todos, 4 waves, pure-native rules — no new external engines)
**Risk:** Medium — a behavior change to a shipping security gate: today ANY npm install hook is CRITICAL; 0.3.0 downgrades ONLY hooks whose source matches a closed safe-shape signature. Mitigated by: downgrade is strictly narrower than the current allow-list surface, default-on-unknown stays blocking (fail-closed preserved), and a golden test pins that every non-signature-matching hook keeps its exact CRITICAL finding today.
**Decisions to sanity-check:** (1) T1 signature-matched install hooks become MEDIUM (visible warning, non-blocking) rather than silent — the gate keeps an audit trail of "we allowed code to run at install"; (2) install-time network fetching is HIGH (blocking) on ALL ecosystems including build-time (`setup.py`, `build.rs`) — a published artifact must carry its own bytes, like opencode's 184 MB binary ships inside optionalDependency carriers; (3) unclassifiable install script ⇒ keeps current CRITICAL (unknown ≠ clean); (4) the T1 whitelist is code (closed list, rulesHash-covered), NOT border.yaml-configurable — config can only `allow` specific findings per G14, never widen signatures.

## Scope

### The constitution (normative — every rule cites a tier)

**Ledger principle**: every byte an install produces must be (a) on the package manager's uninstall ledger, or (b) inside the install root. The manager deletes only what it records ⇒ residue is by-construction impossible for compliant packages. PATH is infrastructure: exactly one stable bin dir per manager, registered in the shell profile ONCE at prefix-provisioning time; packages never touch rc files.

| Tier | Install-time behavior | Verdict | Template evidence |
|---|---|---|---|
| T0 | `bin`/`console_scripts`/binstub/`cargo install` bin — manager-recorded shims only | silent pass | `~/.npm-global/bin/opencode` symlink |
| T1 | lifecycle/build script writes ONLY within install root, no network, source matches a CLOSED safe signature | MEDIUM `residue-in-tree-hook` | opencode `postinstall.mjs`: platformMap → reads own package.json, /proc/cpuinfo, `sysctl -n hw.optional.avx2_0`; hardlinks `node_modules/opencode-<os>-<arch>/bin/*` into `bin/` (link count 2, same inode); zero out-of-tree writes |
| T2 | install/build-time NETWORK fetch (bytes that never passed registry review) | HIGH `residue-install-download` | anti-pattern: esbuild-legacy `curl CDN` |
| T3 | out-of-tree write at install: shell rc / `profile.d` / `git config --global` / `authorized_keys` / `%APPDATA%` / registry Run / PATH-injection lines | HIGH `residue-out-of-tree-write` | anti-pattern: `curl … opencode.ai/install \| bash` rc append |
| T4 | persistence primitives: cron/`systemctl --user`/`launchctl`/XDG autostart/`schtasks` — ANY reference in install-time OR any packed code path reachable from it | CRITICAL `residue-persistence-primitive` | (malware class; no legitimate pass exists) |

## Risks & mitigations

- **R: T1 signature is bypassable by a malicious package mimicking the safe shape with one out-of-signature line.** M: the signature is whole-file (every import + every write-path literal + zero T2/T3/T4 hits), file-length/`require` hops capped at ONE, unknown ⇒ CRITICAL default. A mimic must stay *fully* tree-local — which is exactly what T1 *means*; the downgrade grants nothing beyond "writes vanish with the directory". Residual (runtime-exec of tree bytes at install) equals today's `python -m build`/`gem build` accepted-precedent class; documented loudly.
- **R: regex-family matcher false negatives on obfuscated writes (`"\.bas"+"hrc"`).** M: accepted for static tier (README honesty line: capability ≠ proof); the 0.4.0 sandbox round-trip is the real-fact layer; T4 patterns ALSO run over packed non-script files (string-constant sweep) to shrink the miss window.
- **R: behavior change mid-release confuses users whose hooks flipped CRITICAL→MEDIUM.** M: CHANGELOG names it as the feature's headline; MEDIUM still renders + counts in report (`border check` output visibly differs from 0.2.0 by design); `residue.enabled:false` restores nothing silently — findings just absent with config echo, per trufflehog toggle precedent.
- **R: setup.py scanning overlaps with border's own `python -m build` execution (code runs during stage!).** M: pre-existing documented risk (channels plan); residue scan READS the same bytes build executed — adds detection, not exposure; README already states the trust class.
