## TL;DR (For humans)

<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**What you'll get:** a `border` command that, whenever you say a version is ready, inspects the code the way a border inspector would — the whole git history (including secrets you deleted later), the exact package files that would go to npm/PyPI, your name/email in every commit, leftover AI-session debris — and only then pushes to GitHub + npm + PyPI in one go, with a memory that never re-checks an unchanged version and never lets a checked-off version get re-published over an existing one.

**Why this approach:** mature open-source scanners (gitleaks, secretlint) already solve credential detection better than anything we'd write, so border wraps them and builds only what nobody offers: pre-publish orchestration across three registries, checks on the *built artifact* rather than the repo, AI-era leftovers detection, and a fingerprinted check-ledger. Fail-closed everywhere, because publishing is irreversible.

**What it will NOT do:** no scheduled/automatic pushes (on-demand only); no scanning of third-party dependencies for vulnerabilities; no signing, no secret vault, no platform 2FA configuration; it will never rewrite git history or force-push — if history itself leaks, it stops and tells you.

**Effort:** Large (~20 implementation todos, 7 waves, 3 external engines wrapped)
**Risk:** Medium - fail-closed security tooling with irreversible side effects; mitigated by all-mocked push tests (bare repos + local registry) and a final honesty suite that proves secrets never reach disk unmasked.
**Decisions to sanity-check:** (1) skip-ledger key includes engine versions, remote URLs, the pushed ref-set and the checked target-scope, so a gitleaks upgrade, a newly added remote, or a narrower earlier check re-triggers a full check (may feel "redundant" but is what keeps the gate honest); (2) `border push` without `--yes` is a pure rehearsal; (3) PyPI public upload verification is left as your manual first-run step (test suite stops at twine-check + pre-flight against stubs); (4) the tool installs gitleaks v8.30.1 + python build/twine as its own first step — missing engines are a hard error by design, never a silent pass.
